## 2.1 因果增强架构设计

### 双层图结构

我们提出**双层图结构**（Dual-Layer Graph），融合静态架构知识与动态因果关系：

```
┌─────────────────────────────────────────────────────────┐
│                    Layer 1: 静态依赖图                    │
│                  (Static Dependency Graph)               │
│  - 来源：服务注册表、配置文件、历史追踪数据               │
│  - 节点：微服务实例                                       │
│  - 边：调用关系（A 调用 B）                                │
│  - 更新频率：低（架构变更时更新）                         │
│  - 算法：图遍历、可达性分析                               │
└─────────────────────────────────────────────────────────┘
                          │
                          │ 约束/引导
                          ▼
┌─────────────────────────────────────────────────────────┐
│                    Layer 2: 动态因果图                    │
│                   (Dynamic Causal Graph)                 │
│  - 来源：运行时监控数据（指标、日志、追踪）               │
│  - 节点：服务 + 关键指标（延迟、错误率、吞吐量）          │
│  - 边：因果强度（Granger 因果、相关性）                   │
│  - 更新频率：高（滑动窗口实时更新）                       │
│  - 算法：Neural Granger、NOTEARS、PC 算法                │
└─────────────────────────────────────────────────────────┘
```

### 因果发现算法选择

| 算法 | 适用场景 | 计算复杂度 | 我们的选择 |
|------|----------|------------|------------|
| **Granger Causality** | 时间序列因果，线性关系 | O(n²·t) | ✅ 主要算法（轻量） |
| **Neural Granger** | 非线性因果，深度学习 | O(n²·t·d) | ✅ 核心算法（GPU 加速） |
| **NOTEARS** | 一般因果发现，DAG 约束 | O(n³) | ⚠️ 备选（计算量大） |
| **PC Algorithm** | 约束式因果发现 | O(n^k) | ❌ 暂不使用 |

**我们的方案**：
- **CPU 环境**：使用经典 Granger Causality + 滑动窗口
- **有 GPU 时**：升级到 Neural Granger（PyTorch 实现）

### 因果图构建流程

```python
def build_causal_graph(metrics_window, dependency_graph):
    """
    构建双层因果图
    
    Args:
        metrics_window: 滑动窗口内的监控数据 (n_services × n_metrics × time_steps)
        dependency_graph: 静态服务依赖图 (邻接矩阵)
    
    Returns:
        causal_graph: 带因果强度的有向图
    """
    # Step 1: 使用依赖图剪枝（只检查有依赖关系的服务对）
    candidate_pairs = extract_edges(dependency_graph)
    
    # Step 2: 对每个候选对计算 Granger 因果
    causal_strengths = {}
    for (src, tgt) in candidate_pairs:
        strength = granger_causality_test(
            metrics_window[src], 
            metrics_window[tgt],
            max_lag=5
        )
        if strength.p_value < 0.05:  # 显著性阈值
            causal_strengths[(src, tgt)] = strength.f_statistic
    
    # Step 3: 构建因果图
    causal_graph = create_weighted_digraph(causal_strengths)
    
    return causal_graph
```

## 2.2 多智能体协作协议设计

### 智能体角色定义

| 智能体 | 职责 | 输入 | 输出 |
|--------|------|------|------|
| **协调智能体 (Coordinator)** | 全局协调、策略选择、结果聚合 | 所有智能体报告、因果图 | 最终根因报告 |
| **监控智能体 (Metrics Agent)** | 分析指标异常（CPU、内存、延迟） | 指标数据、因果图 | 异常服务列表 + 指标证据 |
| **日志智能体 (Logs Agent)** | 分析日志模式（错误、警告） | 日志数据、因果图 | 异常日志模式 + 关键错误 |
| **追踪智能体 (Traces Agent)** | 分析调用链延迟 | 追踪数据、因果图 | 瓶颈调用链 + 延迟分解 |

## 2.3 动态推理策略设计

### 故障模式分类

| 故障模式 | 特征 | 推理策略 |
|----------|------|----------|
| **性能下降** | 延迟增加、吞吐量下降 | 追踪优先，沿调用链向上游追溯 |
| **错误率上升** | HTTP 5xx、异常日志激增 | 日志优先，分析错误堆栈 |
| **资源耗尽** | CPU/内存/磁盘接近上限 | 指标优先，定位资源泄漏点 |
| **级联故障** | 多个服务同时异常 | 因果图优先，找根因节点 |
| **间歇性故障** | 时有时无，难以复现 | 多轮迭代，扩大时间窗口 |

### 策略选择器

```python
def select_reasoning_strategy(anomaly_signature, causal_graph):
    """
    根据故障特征选择最优推理策略
    
    Args:
        anomaly_signature: 故障特征向量 {latency_delta, error_rate_delta, cpu_delta, ...}
        causal_graph: 当前因果图
    
    Returns:
        strategy: 推理策略配置
    """
    # 规则 1: 错误率突增 → 日志优先
    if anomaly_signature.error_rate_delta > 0.5:
        return {
            "priority": ["logs", "traces", "metrics"],
            "time_window": "15min",
            "causal_depth": 2
        }
    
    # 规则 2: 延迟增加 → 追踪优先
    if anomaly_signature.latency_p99_delta > 2.0:
        return {
            "priority": ["traces", "metrics", "logs"],
            "time_window": "30min",
            "causal_depth": 3
        }
    
    # 规则 3: 多服务异常 → 因果图优先（级联故障）
    if anomaly_signature.num_anomalous_services > 3:
        return {
            "priority": ["causal_graph", "metrics", "logs"],
            "time_window": "1h",
            "causal_depth": 5
        }
    
    # 默认策略
    return {
        "priority": ["metrics", "logs", "traces"],
        "time_window": "30min",
        "causal_depth": 2
    }
```
